# Praevisa — Session Findings (2026-06-08)

**For: CTO review. Scope: EU Parliament (EP) legislative vote prediction — the §9.6 baseline work and the first prospective-signal test.**

**TL;DR.** We (1) put the §9.6 baselines on reproducible footing and killed a set of
phantom numbers; (2) confirmed that backward, history-only baselines carry *no* edge on
the contested votes that matter; and (3) found the **first genuine positive signal** in
the project — a group's pre-vote **committee** vote predicts its plenary vote markedly
better than those baselines (≈3–4× lower error, statistically significant at n=10).
This is one historical snapshot, not a validated track record. Infrastructure is now in
place to confirm it *prospectively* (blinded pre-commitment, automated weekly). **No
external claim should be made until the prospective result exists.**

---

## 1. The baselines are real now (phantoms removed)

Prior docs cited group-MSE figures of **0.1004 / 0.1508** (and EP-share SSEs of
0.0295 / 0.0242) with no surviving artifact behind them. We rebuilt the §9.6 baselines
as committed, one-command-reproducible code over a frozen 22-file OLP test set
(HowTheyVote.eu data), and **independently replicated** them in a second repo with
separate code and a fresh data pull.

| metric | phantom (old) | real (reproduced, 2 independent code paths) |
|---|---:|---:|
| Baseline A group MSE | 0.1004 | **0.1656** |
| Baseline C group MSE | 0.1508 | **0.3240** |
| A EP-share SSE | 0.0295 | **1.5054** |
| C EP-share SSE | 0.0242 | **1.6879** |

The phantom numbers do **not** reproduce under any faithful build; the 22-file result
does, exactly, twice. All four §9.6 methodology decisions (abstention handling, the
Baseline C partition, weighting, term scope) are frozen and documented.

## 2. Backward baselines have no edge where it matters (the bar)

Robustness (cluster bootstrap, 10k resamples): Baseline A — the per-group historical
mean — is **statistically indistinguishable** from a pooled-mean floor on the full set
(Wilcoxon p = 0.35). We then stratified onto the *contested* subset (a re-evaluation
holding predictions fixed). Result: **the contested subset does not rescue Baseline A —
it indicts it.** On no contested cut does it beat the floor; on rejected (genuinely
lost) votes it is *worse* than the pooled mean. Conclusion: "what each group usually
does" is not a forecasting edge. **A real model must beat the pooled-mean floor on the
contested subset, prospectively.** That is the bar.

## 3. First positive result — the committee→plenary signal clears the bar

Hypothesis: on contested first-reading files, a group's **committee-stage vote**
(cast weeks before plenary) predicts its plenary yes-rate better than the floors.

We built the data pipeline to test it (see §4), yielding 13 usable (committee-signal,
plenary-outcome) pairs, 6 contested. Stage A grades the signal, time-split and
pseudo-prospective (floors fit only on data dated before each target; committee vote is
genuinely pre-vote). Metric: per-group MSE, paired bootstrap CI + Wilcoxon.

| subset | n | committee MSE | floor MSE | 95% CI of diff | Wilcoxon p |
|---|---:|---:|---:|---|---:|
| all pairs vs pooled-mean | 10 | **0.053** | 0.170 | [−0.185, −0.047] | **0.020** |
| all pairs vs Baseline A | 10 | **0.053** | 0.178 | [−0.199, −0.047] | **0.020** |
| contested vs pooled-mean | 6 | **0.050** | 0.213 | [−0.249, −0.056] | 0.062 |
| contested vs Baseline A | 6 | **0.050** | 0.231 | [−0.255, −0.064] | 0.062 |

- The committee signal beats both floors on **9 of 10** pairs, by a **≈3–4× error
  reduction**. Significant on all pairs (CI excludes 0, p = 0.020).
- On the contested subset the effect is *larger*; the CI still excludes 0, but n=6
  cannot reach Wilcoxon p<0.05 (a power limit, not a weak effect).
- **Adversarial check passed:** the cleaner *report-adoption* committee vote is the
  strongest signal (MSE 0.004 vs 0.26 on contested), not the near-tautological
  post-trilogue "provisional agreement" vote — so this is real signal, not a
  same-text artifact.

## 4. Infrastructure built this session (all committed, reproducible)

- **Procedure→plenary resolver** (`praevisa/resolve_plenary.py`). The HowTheyVote API
  *list* endpoint is a capped/rolling window (~2,352 of ~24k votes) and silently omits
  older votes — it cannot enumerate. We switched to HTV's **bulk export** (complete
  ~24k-vote table) for deterministic procedure→vote resolution; per-group stats via the
  reliable by-id detail call.
- **Committee scraper, full 20-committee set** (`committee_scrape.py`). EP committee
  roll-calls are PDF-only (no API) and the source page is a **rolling window** — so the
  scraper now **merges/accumulates** (never overwrites) and the corpora are committed,
  not regenerable-from-scratch.
- **Stage A backtest** (`praevisa/stage_a.py`) — the pseudo-prospective grader above.
- **Stage B pre-commitment harness** (`praevisa/stage_b.py`) — writes immutable,
  hash-stamped per-group predictions for files with a committee vote but no plenary vote
  yet; grades only plenary votes dated strictly *after* the commit. The git history is
  the pre-commitment proof.
- **Automated weekly cadence** (`scripts/stage_b_cadence.sh` + macOS LaunchAgent).
  Scrape→grade→predict→verify→commit, Mondays 09:00, catch-up on wake. First run
  completed end-to-end (commit `76a2e4b`).

## 5. Honest limitations (do not skip)

- **Stage A is n=10 (6 contested), one snapshot.** The report-stage contested evidence
  is ~2 effectively-independent files (two are twin procedures). Encouraging, not
  conclusive.
- **Pseudo-prospective, not pre-committed.** Stage B is the real test; its contested
  predictions accrue over **2–6 months** (right now there are 0 contested *pending*
  targets — the contested files already voted).
- **Scope is narrow.** The signal buys ~weeks of lead time on files that have reached
  committee. It does **not** forecast far ahead, nor cover Council/trilogue — where much
  of the commercial value is hypothesized to live and where nothing is built yet.
- **Commits are local** (no git remote). For an externally defensible pre-commitment,
  add a remote + push at predict-time.
- The competitive landscape is unchanged: a better-resourced ML competitor already does
  forward EP prediction at ~80% on millions of votes. Our defensible ground is the
  contested/upstream subset this signal targets — *if* it validates prospectively.

## 6. Recommendation

The wedge is **no longer purely hypothetical** — for the first time a pre-vote signal
beats the established floor on the contested subset. But it rests on 10 files and one
snapshot. **Do not put this in front of investors or in marketing yet.** Let the weekly
cadence accumulate a *prospective, blinded* contested track record over the next couple
of months; then we either have a defensible validated edge or we learn the snapshot was
lucky — both far more valuable than asserting it now.
